## 4. Roles & auth (how it works now)

- **AUTH_MODE=clerk is LIVE.** `getServerIdentity()` (`src/lib/role-server.ts`) reads
  the Clerk session → looks up `users` table (`clerk_id → role, linked_coach_id`).
  No users row = role `va` (least privilege).
- **4 login roles:** owner, coach, sales, va. **Head coach is NOT a login role** —
  it's `role='head_coach'` on the `coaches` record (Angus). Head coach sees all
  coaches' client+performance data but only their **own** pay, and no personal info
  of others.
- **Admin impersonation ("Open their portal"):** on Coach Overview, owner clicks it →
  `startImpersonation(coachId, returnTo)` sets an owner-only cookie
  (`hq-impersonate-coach`) that `getServerIdentity` honours → whole app renders as
  that coach, with an "Exit to admin" banner that returns to the page they came
  from. Server-enforced; a non-owner can't impersonate.
- **Embed:** the GHL iframe embed stays on the password gate (decision), not Clerk.

## 10. Gotchas / decisions to carry forward
- **Deploy = CLI only** (project not git-connected). Browser redeploy ≠ new code.
- **Sandbox git lock:** the Cowork sandbox can't hold the git lock, so it can't
  commit; a parallel Claude Code tab (host-side) commits. Working tree is the truth
  for deploys.
- **NO-CONTACT rule (non-negotiable):** no real client/lead may be contacted by the
  HQ. Every outbound path calls `assertOutreachAllowed()` (OFF unless
  `OUTREACH_ENABLED="true"`). Do not flip it.
- **Secrets are owner-only:** never enter credentials/tokens into fields; never
  commit `.env*`. Schema/migrations, auth/roles, secrets, deletes = owner hard-stops.
- **UI copy:** no em dashes; tabular numerals + tight negative letter-spacing on
  display numbers. Match `reference/prototype.html` look; reuse primitives.
- **Rotate flagged secrets** (from earlier): the Clerk live secret Kai once pasted +
